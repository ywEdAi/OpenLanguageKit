# 用知识点给原语库查漏补缺（2026-11-09）

## 做了什么

我把英、日、中三套课程知识库（共 950 个知识点）逐个绑定到教学原语上。绑定的起点是 `edu-ai-builders/language-learning-asset-library` 现有的 48 个英语 asset。每个知识点都写明：用哪个原语为主、哪些为辅，以及这一次比较什么、用什么材料、检查什么。凡是现有原语接不住的知识点，就补新的原语。

| | 开始时 | 结束时 |
| --- | ---: | ---: |
| 原语 | 25 个（由 48 个 asset 归并而来） | 56 个 |
| 有可运行英语实现的原语 | 25 | 25，其中 5 个只是部分实现 |
| 只有契约、尚无实现的原语 | 0 | 31 |
| 绑定了原语的知识点 | 0 | 950 / 950 |

每个原语都有完整契约：

- 针对的困难、学习者持续处理的对象、三步动作、系统回应、界面（儿童版与成人版）
- 触发条件与禁用情况
- 检查规则（两头同时卡）、独立完成与提示后完成的区分
- 证据最多能支持的判断、不许推出的判断
- 提示阶梯与撤除条件、反向那一半
- 失效方式与对抗测试、纵向叠合、各语言参数

## 发现的主要缺口

### 1. 现有库从 B1 往上开始，入门层几乎是空的

现有 asset 都是中国学生学英语的阅读、写作和篇章能力，面向 B1 以上。知识点在入门阶段最需要的动作，原来都没有原语：

- 辨音：最小对立、声调、音高
- 拼读与文字：英语自然拼读、假名、汉字字形与笔顺、注音逐步撤除
- 变形：日语活用、英语屈折
- 语序与格标记：日语助词、中文介词和"把"
- 量词与可数性
- 低龄活动：听指令做动作、看图描述、排序复述

### 2. 交际功能是单个最大的缺口

三种语言共有 86 个功能类知识点以"交际回合与分支"为主要原语：问候、点餐、问路、道歉、投诉、打电话等。这个原语还没有任何实现。现有的 c06（场景词群）和 c58（信息差，要在页面之外找真人对话）只能作为辅助。契约里规定，对方的反应是预先写好、经人检查的分支，不是聊天机器人，也不对语音自动打分。

### 3. "对立形式选择"一个原语装了太多不同的判断

第一轮绑定时，它是 181 个知识点的主要原语。三种语言的绑定结果都指出，它把好几类本质不同的判断混在一起，于是拆出三个新原语：

- **梯度定位**：确定度、义务、程度。例如 must/might、可能/一定、かもしれない/はずだ。
- **视点与方向**：あげる/くれる/もらう、ていく/てくる、来/去、被、bring/take。
- **后句限制核对**：后句能接什么。例如 と/たら/ば/なら、たとたん、只有……才、unless、when 从句里用现在时表示将来。

拆完以后它还剩 140 个主要绑定，主要是时体和真正的形式对立。

### 4. 只在某一种语言里才暴露的困难

- **日语**：变形规则是 60 个知识点的主要原语，比例最大；格助词 19 个，后句限制 18 个。对中文母语者来说，难点集中在读音（音读、训读、连浊、熟字训）和同形异义（大家、手紙），不在字义。
- **中文**：语序槽位是最大的类别（16 个）。华裔儿童会说不会读，不应该先学拼音，因此补了"口语词连到文字"。
- **英语**：14 个知识点挂在梯度定位上（情态与确定度），6 个挂在可数性上。

### 5. 第二轮补上的跨语言原语

这些原语各自只对应少数知识点，但三种语言都需要：

- 读音选择：音训、多音字、同形异音词
- 同形异义核对
- 翻译与中介对齐
- 数位体系转换：万/亿 和 thousand/million 之间
- 变体对照：方言、繁简、英美
- 字面与言外之意
- 词典义项选择
- 输入法转换
- 音素意识游戏
- 会话修复与接应
- 按真实格式填写

## 新建实现的优先顺序（按受益知识点数）

以下数字是"以它为主要原语"的知识点数，按 en / ja / zh 列出。

1. **交际回合与分支** 34 / 36 / 16。缺口最大，而且决定成人日常、商务课程能不能用。
2. **变形规则用于新词** 24 / 60 / 3。日语入门的主干。
3. **语序槽位** 7 / 10 / 16，以及 **格与语义角色标记** 2 / 19 / 7。日语和中文的入门语法。
4. **最小对立辨音** 5 / 12 / 2，以及 **声调与音高轮廓** 3 / 4 / 2。不做自动语音打分，靠听辨、自我对照和真人听者。
5. **后句限制核对** 3 / 18 / 5。日语 N3–N1 的大部分句型。
6. **字形构件与书写**、**音形对应拼读**、**读音选择**。文字入门，按语言各做一版。

`coverage.md` 列出每个原语绑定了哪些知识点。三种语言里，主要原语还没有任何实现的知识点分别是：英语 125/353，日语 204/386，中文 91/211。

## 纵向叠合示例：同一个对象，几个原语一起起作用

1. **日语 · 在餐厅点餐**（ja-life 方案 A1）
   - 对象是一份真实菜单加一段预先写好的点餐对话。
   - 先用"真实单据扫读"在菜单上找到要点的东西和价格。
   - 进入"交际回合"，点餐时数量要用助数词。"计量方式"的检查直接作用在这一句上：ひとつ/ふたつ、一杯/二杯。
   - 店员说得太快时插入一个"会话修复"时刻。
   - 结束时留下的是学习者自己说出的那份订单，不是几道分散的练习。
2. **中文 · 华裔儿童读出已经会说的话**
   - 对象是孩子自己说出的一句话，例如"我昨天去公园了"。
   - "口语词连到文字"把每个词连到汉字。
   - 不认识的字由"字形构件"拆出部件。
   - "注音逐步撤除"只给还没读对的字保留拼音。
   - 最后孩子读的是自己的句子，读对哪些字、哪些是看拼音读的，都分别记录。
3. **英语 · 写一封分寸得当的建议邮件**（adult-work 方案）
   - 对象是学习者自己的邮件草稿。
   - "梯度定位"调整 must/should/might 的分量，"语域校准"按收件人的关系调整措辞，"来源与确定度"检查每个主张有没有依据。
   - 改动全部落回同一封邮件。这正是 asset library 文章里说的：活动要累积到作品上。

## 仍需讨论（各批次提出、本轮没有改动）

- **可能还要拆分的原语**：
  - 语块采集 c02 与搭配网 c05
  - 查跳分诊 c26 与语境猜词 c27
  - 修饰位置 c18 与并列对齐 c21
  - 字面与言外之意：成语、比喻与会话含义
  - 用法边界：语法错误边界与搭配边界
- **边界需要写清的成对原语**：
  - 梯度定位与语域校准，c17 同时挂在两者下面
  - 最小对立辨音与声调轮廓，长短音和声调对立
  - 视点与方向与格标记，共用一张场景图
  - 变体对照与语域校准
- **仍未找到合适原语的 3 个知识点**：
  - 英语"按读者规划内容"
  - 日语"原稿纸格式"
  - 日语"鞠躬等非语言礼仪"
  - 都先绑在最接近的原语上，记录在各语言 `primitive-map.json` 的 `gaps` 里。
- **实现前要先核对许可证**：笔顺数据（KanjiVG、Make Me a Hanzi）的许可证是相同方式共享 / LGPL 一类。中日笔顺标准也不同。
- **跨原语的间隔复习**：现在暂时放在"先回想，再对照"里，没有单独的原语。
- **中文缺一个知识点**：没有"拼音输入"知识点，可以对照日语的 `kt:ja-orth-input` 补一个。

## 第二步：入门层积木与工作台（2026-11-09）

第一个缺口是入门层几乎为空，所以先补了文字与语音的入门积木，放在仓库根目录的 `blocks/`，说明见 `blocks/README.md`。它们是三个原语的第一批实现。

| 原语 | 新实现 | 状态 |
| --- | --- | --- |
| 音形对应拼读 | 音节表（平假名、片假名、拼音、英语字母、自然拼读、法语字母）和拼读（英、法、日、中） | 有实现 |
| 声调与音高轮廓 | 普通话声调（含变调）和日语高低音调 | 有实现 |
| 字形构件与书写 | 汉字部件（中文 96 字，日语 55 个 N5 汉字） | 部分实现：没有笔顺和书写练习 |

主要原语还没有任何实现的知识点：

| 语言 | 之前 | 之后 |
| --- | ---: | ---: |
| 英语 | 125 | 115 |
| 日语 | 204 | 193 |
| 中文 | 91 | 81 |

按"主要原语在这种语言里有没有实现"分，日语有 181 个知识点、中文有 120 个知识点的主要原语只有英语实现。这些实现可以借用改写，但还没有日语或中文版本。这是下一阶段的主要工作量。

这批积木的约定：

- 法语没有课程，只用来说明"加一种语言只需要一个数据文件"。
- 声音全部来自浏览器语音合成，任何一项都可以换成真人录音，也都不打分。
- 日语音高和单独音素的合成最不可靠。
- 待母语者核对的条目放在每个数据包的 `review` 列表里，没有放进练习。

`workspace/` 是给审阅用的工作台，可以把知识图谱、原语和学习页面放在一起看，并当场记录反馈。启动命令是 `python3 workspace/serve.py`。

## 边界

- 契约和绑定是编辑性设计，没有经过教师审核或学习者试用，不声称有学习效果。
- `spec` 状态的原语只有契约，没有界面。
- 没有改动 asset library 等其他仓库，现有 asset 只是按 ID 引用。工作台只在本地挂载它的页面。
